# Device Attestation with TPM 2.0

Here I'll describe how TPM attestation works and how you can implement
your own attestation server.

## What is a TPM?

A Trusted Platform Module (TPM) is a piece of hardware that can guarantee
it hasn't been tampered with.
For our purposes, a TPM can prove (attest) to knowledge that it would only
know.

## What is a TPM's API?

For our purposes, a TPM that implements the TPM 2.0 spec has the following:

1. An Endorsement Key (EK): a public/private key combination that uniquely
identifies the hardware module.
The private key is hidden inside the module and cannot be exported.
The public key is available, and has been signed by the manufacturer in
some fashion.

An important aspect of the Endorsement Key is that it cannot be used for
signing: the TPM will not let you encrypt any data with its private key.
Instead the TPM can only *decrypt* data that has been previously encrypted
with its public key.

2. Slots to hold Attestation Keys (AKs).
These are public/private keys for which the private key is also held within
the TPM itself.
Unlike the endorsement key, these key can be used for signing.


## What is an Attestation Server's job?

The user's device is going to generate a public/private key pair, with the
intention of getting that key pair signed by a Certificate Authority.
The Certificate Authority delegates the following responsibilities to the
Attestation Server:

1. The query comes from the actual user's device, and is not an impostor.
This guarantees that the CA is communicating with the correct hardware.

2. Verify that the key pair was generated by the TPM.
One worry is that careless software is generating the public/private key
in software, and storing the private key in a manner vulnerable to extraction.
If the key pair was generated inside the TPM, the private key is not able
to be extracted.

3. Verify that the client device is running an expected operating system.
This is a check that requires OS support, and is something I have not implemented.

## How are these checks performed?

These checks are initiated by the user device itself, so the first
message that comes to the attestation server contains the following:

a. The TPM Endorsement Key's public certificate and chain.
The server immediately checks that the EK validates to a preconfigured trusted root.
This process is described in PowerShell below.

b. The Attestation Key's public certificate.

c. Metadata, including TPMS_CREATION_DATA, TPMS_ATTEST, and TPMT_SIGNATURE
This information allows the server to verify that the EK and AK are connected.

The server signs the Attestation Key, but doesn't immediately send back
the signature.
Instead it encrypts the signature using the Endorsement Key's public key
before sending it back.
The only way for the signature to be utilized is if the user's device
has access to the TPM's EK private key, and thus the TPM is on the machine.

### Appendix: Verifying a Certificate Chain

```powershell
> # Device certificate
> $TpmCert = (Get-TpmEndorsementKeyInfo).ManufacturerCertificates[0]
>
> # Certificates from the manufacturer website
> # For my laptop the chain is:
> #      GlobalSign TPM Root
> #   -> STM TPM EK Root
> #   -> STM TPM EK Intermediate 06
> #   -> My TPM's EK
> Invoke-WebRequest -Uri 'https://securet.globalsign.com/cacert/stmtpmekint06.crt' -OutFile "$env:TMP\ek_int.crt"
> Invoke-WebRequest -Uri 'https://securet.globalsign.com/cacert/stmtpmekroot.crt'  -OutFile "$env:TMP\ek_root.crt"
> Invoke-WebRequest -Uri 'https://securet.globalsign.com/cacert/gstpmroot.crt'     -OutFile "$env:TMP\root.crt"
> $EkIntCert  = Get-PfxCertificate -FilePath "$env:TMP\ek_int.crt"
> $EkRootCert = Get-PfxCertificate -FilePath "$env:TMP\ek_root.crt"
> $RootCert   = Get-PfxCertificate -FilePath "$env:TMP\root.crt"
>
> # Quickly check that I downloaded the right certificates
> $TpmCert.Issuer -eq $EkIntCert.Subject
True
> $EkIntCert.Issuer -eq $EkRootCert.Subject
True
> $EkRootCert.Issuer -eq $RootCert.Subject
True
> $RootCert.Issuer -eq $RootCert.Subject
True
>
> # Validate the certificate chain
> $Chain = [System.Security.Cryptography.X509Certificates.X509Chain]::new()
> # GlobalSign doesn't provide CRL or OCSP endpoints
> $Chain.ChainPolicy.RevocationMode = 'NoCheck'
> # The root certificate is not installed as trusted on the current machine
> $Chain.ChainPolicy.VerificationFlags = 'AllowUnknownCertificateAuthority'
> # The parent certificates must be available to verify the base cert
> $Chain.ChainPolicy.ExtraStore.Add($RootCert)
> $Chain.ChainPolicy.ExtraStore.Add($EkRootCert)
> $Chain.ChainPolicy.ExtraStore.Add($EkIntCert)
> $Chain.Build($TpmCert)
True
> # The only "error" should be UntrustedRoot:
> # the certificates properly sign each other,
> # but the toplevel root certificate isn't trusted by the current user.
> $Chain.ChainStatus.Status
UntrustedRoot
```
